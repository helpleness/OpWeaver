# Qwen 扩容后拒答增加：逐 token 与记忆接口诊断

本轮只诊断，不训练、不改部署决策。证据门槛仍为 >0.99，生成门槛仍为所有生成 token 的最小条件概率 >0.8，并要求正常结束。两个模型各复现原问法60题、新问法60题；240条原始文本逐字一致、原分数差异小于1e-6，两个 adapter 文件 SHA256 均未改变。

主要结论：生成概率门控混淆了“怎样表达”与“事实是否正确”。1.5B新问法下，24条目标事实匹配却被拒答的输出中，19条只有事实片段之外的 token 没过门槛。同时仍有1条真正的跨字段混读，局部替换记忆接口能修正其内容。模型升级改善了部分理解能力，但没有修复门控指标和记忆接口。

## 1. 拒答增加的数量分解

全部使用上一轮预先固定的严格目标字段匹配，不为本轮改评分。数字是同一批60道新问法；“匹配”不等于已证明整句话没有额外错误。

| 指标 | 0.5B | 1.5B |
|---|---:|---:|
| 原始生成匹配目标事实 | 57 | 59 |
| 匹配且最终放行 | 39 | 35 |
| 匹配却被拒答 | 18 | 24 |
| 未匹配并被拒答 | 3 | 1 |
| 总拒答 | 21 | 25 |
| 匹配却拒答：所有目标事实 token 均 >0.8 | 15 | 19 |
| 匹配却拒答：至少一个目标事实 token ≤0.8 | 3 | 5 |

因此总拒答的净变化是：多拦6条目标事实匹配的输出、少拦2条错误输出，合计增加4条。不是同样4题统一退步：逐题有16条从放行变成拒答、12条从拒答变成放行、23条都放行、9条都拒答。两个模型同题的概率分布不同，数值门槛相同不代表实际风险相同。

原问法两者均原始60/60匹配、最终57/60放行。这一问题在改写后更明显，但不能归咎于“用户不会提问”；问题分布变化暴露了当前训练和决策设计的不足。

## 2. 哪些 token 拦住了正确事实

1.5B的24条匹配却拒答中，最低分 token 位于：措辞15条、标点3条、结束符1条、目标事实片段5条。全部正常结束，排除了40-token截断导致这些拒答。

下面概率均为该位置给定前文后的条件概率，不是整条答案正确概率；行号为 traces.jsonl 中记录的零起始 index。

| 行号 | 实际生成 | 拦截位置及概率 | 目标事实片段最低概率 |
|---|---|---|---:|
| 33 | 那件事发生在第2天。 | 开头“那”0.6024；备选“第”0.3654 | 0.9985 |
| 65 | 当时感到安心。 | “感到”0.6881；备选直接接“安心”0.2868 | 0.9996 |
| 69 | 当时情绪状态是高兴。 | “。”0.5311；备选“的”0.4687 | 0.9905 |
| 47 | 那次的事情是收到礼物。 | 结束符0.7849 | 0.9929 |

比如“当时感到安心”与“当时安心”存在表达竞争；目前取全句最小概率，会把这种竞争变成拒答。候选 token 不能证明其后完整续写一定正确，但实际正确输出、逐 token 位置和后面的干预共同支持这一机制。

事实片段中的低概率也不一定意味着事实丢失。例如行59直接回答“弄坏杯子。”，首 token“弄”0.4768，与开头“那次”0.4208竞争；这是直接给答案还是先铺垫的竞争。行45则在“那次的事情是”之后，“叫”0.7179与“和”0.2331竞争，不能简单当作纯措辞问题。不能把这5条一概视为同一原因。

作为诊断，为新问法手动提供正确字段对应的固定开头，再让同一模型续写：1.5B原来24条匹配却拒答的样本中，17条续写仍匹配且续写所有 token >0.8；0.5B对应11/18。这里使用了实验者知道的目标字段，而且不计算强制开头的概率，**不是正式成功率提升，也不是可直接上线的修复**。部分人物题仍会扩写并低分，说明固定开头并不能解决全部情况。

## 3. 记忆在，但生成器仍可能混读

新问法下，两模型上一轮的正确寻址且证据通过均为60/60。本轮直接取同一 SQLite 中实际选中的记录：两者每题的目标字段探针、全部8个槽的分类探针均正确（60/60）。这些探针来自已有辅助监督，只说明有限词表中的信息能被辅助分类头解码；它们不参与部署生成，也不证明任意经历都能被保存。

1.5B唯一未匹配样本是行53：

- 问题：“花园项目第1次讨论，这次经历里具体出了什么事？请说出发生的事情。”
- 应答事件：“提出建议”；其他槽包含人物“小杨”、关注点“任务结果”。
- 实际生成：“那次和小杨交流，提出任务结果。”，最低概率0.2591，已被拒答。
- 同一事件原问法“那次的事件是什么？”生成“那次的事情是提出建议。”并通过门槛。
- 事件槽辅助分类头给正确类别的概率0.999989。
- 仅强制事件回答开头后，仍生成“那次的事情是和小杨交流意见。”，没有恢复目标事实。
- 保持问题与其余槽不变，只把事件槽的4个连续输入替换为训练时使用的正确事件词嵌入，输出恢复为“提出建议。”；最低概率0.6151，仍未通过原门槛。

这将该样本的问题定位到连续记忆输入与语言生成器的交互：潜变量中可解码出目标信息，但当前接口在新问法下没能稳定约束生成内容，混入了其他字段。局部干预支持记忆接口参与故障；不能据一个样本断言一定是某一层或某个注意力头出错，也不能完全排除指令理解的交互影响。

替换全部槽后，生成“小杨提出了一些关于花园项目的建议。”。固定字符串评分仍判未匹配，但人工阅读可见“提出建议”的语义已恢复；同时它增加了行为主体的归属，原事件文本未明确是谁提出建议，不能视为已验证的完整正确答案。这也是不能只看匹配分数的例子。所有替换都使用真值，只用于定位，未写入正式记忆库或权重。

0.5B的3条问原因却答情绪的样本是另一类问题：直接给“因为”开头后，3条都能读出正确原因；只替换原因槽输入则3条仍答情绪。这更支持问题意图/输出字段选择错误，而非原因没有存进去。1.5B已修正了这3条，但出现上述1条新的混读。

## 4. 为什么当前训练容易出现这种现象

代码核查得到的事实：

1. 基座冻结；读取阶段也冻结写入器，仅训练记忆到连续输入的投影、位置参数和空记忆。更换基座不会自动带来独立的字段选择器或事实核验器。
2. 训练集768条记录中512条标记为已存，每条固定两种事件表述、每字段两种问题视图；每字段的目标回答只有一种固定句式。这足以学习受控对应，尚未覆盖自由措辞、角色归属和跨字段干扰。
3. 语言损失是答案 token 的平均交叉熵；上线规则却要求每一个 token 的概率都超过0.8。训练目标并未直接优化“在正确字段上有证据支持的回答是否可信”。
4. 生成概率没有校准为事实正确概率；不同模型的词概率分布不可直接用相同数值解读为相同可靠性。当前结果只支持这两个具体适配器的比较，不能推出“大模型必然因表达丰富而更爱拒答”。
5. 槽位分类损失监督“信息能否被分类头读出”，词嵌入对齐和语言损失监督另一条读取路径。前者达到100%并不保证冻结语言模型在所有问法中使用正确槽位；行53提供了直接反例。

因此，问题同时涉及模型接口、窄分布训练和置信度设计，不能用“训练文本没到几个GB”单独解释。预训练模型已经学过语言，本实验需要验证的是新增记忆接口是否把事实、意图和表达稳定连接起来。

## 5. 下一版应该验证什么

后续应把问题字段选择、记忆事实读取、自然语言表达和证据核验分开训练/评估；加入字段互换、相同问题不同记忆、同事实不同措辞等对照，尤其监督问原因/情绪、人物/事件的差异。表达可以变化，事实依据必须一致。

拒答应由经过独立验证的“问题—记忆—候选答案”一致性支持，而不是把全句最小词概率当事实可信度。此处**没有直接删除措辞 token、换用事实 token 分数或降低门槛**：诊断中的事实范围使用真值定位，真实推理不能这样取巧。下一版即使换评分器，也必须用独立校准集约束错误接受率，并在新事件、新句式、空记忆、错误地址和矛盾记忆上验证；只保留数字0.8本身不能保证风险不变。
