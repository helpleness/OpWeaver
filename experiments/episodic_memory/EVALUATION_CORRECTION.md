# 评分方法纠正与证据审计（2026-10-26）

后续已完成取消固定拒答监督的实际重训与 48 条输出逐条核验，见 [后续实验报告](FACT_READER_RESULTS.md)。下文“本轮没有训练”仅指此前评分纠正阶段。

用户指出的问题成立。之前把固定句式、原型能力范围、事实正确性混在一起评分，不能支持“模型已经学会可靠拒答”的结论。本文纠正解释，不改写历史权重或原始输出。本轮没有训练、重新推理或降低门槛。

## 已核实的问题

1. `outcome()` 只有完全匹配“我没有这段经历的记忆。”才算拒答；其他说法可能直接记错。正确事实也可能因不包含某个连续字串而记错。反之，包含答案词不保证整句正确，例如否定、人物角色颠倒、额外编造因果关系。
2. 176 个历史“负例”混入了 16 道多字段题和 16 道是非题。这 32 题的可用记录足以回答，只是不符合当时单字段原型的范围约定。回答它们可能违反历史提示，但不能因此判为事实错误。另有 16 道未指明事件的问题，应区分澄清、带限定的回答与猜测。
3. 最终记忆系统的 240 次输出是：181 次生成前拦截、4 次生成后拦截、55 次生成内容交付。拒答文本多数由控制器返回，不是语言模型现场生成。“176/176 负例拒答”只能描述旧任务约定下的系统行为，不能当作自由生成拒答能力或普遍零幻觉的证据。
4. 4 次生成后拦截的原始回答都表达了正确关注点：自身表现、对方需求、具体细节、环境变化。它们被精确答案模板挡住。最终用户收到的仍是拒答，不能把这 4 次端到端结果改成答对。
5. 原始无上下文 Qwen 没有获得经历证据。不能把它在这些题上的未作答解释成记忆模型改善了语言能力。`chat_no_context` 还存在 160/240 次达到 40-token 上限的问题；截断也要单列。

训练代码同样存在固定措辞监督：旧 reader 阶段把约 15% 的随机移除记忆样本，以及缺失目标字段的样本，统一用该固定句做语言交叉熵目标。这样的接口监督并非一概不允许，但它不能证明模型理解了证据缺失；再用相同句子评分会偏向训练约定。

## 现在如何评审

`semantic_review.py` 不假装是一个自动理解语言的评分模型。它生成证据包，要求有署名、依据和原始输出绑定的语义评审。没有评审的输出是未判定，不是错误或正确。

| 维度 | 判定依据 |
|---|---|
| 事实可答性 | 本条件实际可用的记录；缺失、冲突、事件不明确分别记录 |
| 回应行为 | 回答、表示不知道、请求澄清、混合回应、无法判断 |
| 目标完成情况 | 所问事实是否正确、是否遗漏所问字段；不靠逐字匹配 |
| 全部事实依据 | 逐项声明及证据引用；分别标注有依据、矛盾、无依据、不确定 |
| 指令与格式 | 与事实正确性分开；旧提示的范围禁令和固定措辞不能充当事实标签 |
| 输出与系统路径 | 是否截断；是否调用生成器；是否被控制器拦截 |

对于记忆系统，证据包中的记录代表写入系统的可用经历，不意味着生成器确实成功读到了它们；读取成功需要另做内部诊断。评审器可看原始事实来检验正确性，生成器仍不读取聊天原文。

自动生成的题型参考只解释这个已知合成测试集的生成语义，不是通用问题理解器。未标注的新多字段/是非句式会报错，不会静默套用标签。

## 保存输出的定向复核

共整理六种条件的 **1,264 条输出**：原始 Qwen 四种条件 784 条，上一版记忆系统 240 条，最终记忆系统 240 条。记录了源文件哈希、可用证据、实际提示、输出结束标志；另存模型身份映射，方便后续隐藏模型名称的复核。上下文和指令仍可能暴露条件，不能称为双盲。

本轮由本对话助手**非盲、非独立地复核 13 条定向选出的案例**，其余 1,251 条仍未评审。另核查上述 4 条被拦截的生成内容。不能把这个特意选出的样本推算成总体准确率。

| 原始输出例子 | 旧评分/处理 | 纠正后的解释 |
|---|---|---|
| “交流对象姓名：未知”（无经历证据） | 错误 | 表示不知道；仅措辞违反旧约定 |
| “交流对象：小陈；注意力所在：自身表现” | 错误 | 两项事实都有依据；违反旧单字段范围约定 |
| “是不是安心？”→“否”，记录为紧张 | 错误 | 事实正确；违反旧的是非题范围约定 |
| 同一类问题→“是”，记录为生气 | 错误 | 确实与事实矛盾，仍应判错 |
| “把注意力放在了他人的反应上” | 错误 | 与“他人反应”语义一致 |
| 正确回答“生气”，又说“关注时间安排，因此生气” | 正确 | 目标情绪正确，但额外因果关系没有证据 |
| 先说姓名未提供，又说自己参加了该次交流 | 错误 | 混合回应且有无依据断言，不能凭拒答词通过 |

逐条判断与证据在 [reviews.jsonl](runs/semantic_review_01/reviews.jsonl)，覆盖情况在 [summary.json](runs/semantic_review_01/summary.json)，控制器审计在 [controller_audit.json](runs/semantic_review_01/controller_audit.json)。这些是审计记录，不是新模型成绩；所有总体 `semantic_accuracy` 为 `null`。

## 已落地的修改与未解决部分

- 旧评估/原始 Qwen 对比脚本必须显式使用 `--legacy-protocol`，新输出标注为历史约定分数。旧数字保留用于复现，不再作为通用语义准确率。
- `train_semantic_memory.py` 的读取训练默认只选择已知目标字段，并保持对应记忆存在；不再训练固定拒答文本。可用性分类目标仍保留。`--legacy-refusal-target` 仅用于复现历史 reader 目标。
- `ask_checked` 新增 `action`、`decision_source`、`model_generated`，区分控制器行为与生成器输出；不改变历史门槛和接受策略。
- 21 项相关测试通过，覆盖证据隔离、损坏记录、多字段/是非标签、冲突、评审绑定、未评审覆盖、读取训练目标和门控行为。

**尚未解决：**现有权重仍承袭旧训练目标；意图分类仍将多字段/是非题列为原型不支持，生成接受规则仍依赖答案模板。移除未来训练的固定拒答目标不等于已经训练出自然语言拒答能力，也不会修复已有 checkpoint。不能仅靠增加拒答同义词或补答案模板宣称解决。

下一次能力比较应先冻结改正后的标签、允许语义等价表达的规则和完整生成预算；保留同题原始基座、无记忆、正确记忆、错误记忆对照。生成式未知/冲突说明应基于具体证据训练，允许多种自然表述，不能靠统一一句话拿分。对新输出逐项核查并引入独立复核/分歧裁定，报告覆盖率与分条件结果；已查看的旧测试只作回归集，不能继续称为未见测试。
