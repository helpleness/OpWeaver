# 本机最小实验结果

这是首轮旧模型的历史报告。后续改写改进与配对测试见 [第二轮结果](PARAPHRASE_RESULTS.md)。

2026-10-26，实验目录 `runs/pilot_03`。结论：**受控事件内容能经过学习编码、落盘并在新进程中回忆；自由表达泛化尚未成功。**

## 已实现的链路

受控中文事件 → 从随机参数训练的Transformer → 4×128内容槽和64维地址 → 在线分组 → SQLite持久化 → 问题向量选择分组和事件 → 交叉注意力读取内容 → 答案分类。

数据库不保存原文或答案标签。运行时 `demo` 只加载模型、数据库和当前问题，不访问数据集。这里仍有学习得到的寻址/检索，但检索对象是事件潜在表示，而非聊天原文。并非把所有经历永久写进模型权重。

## 训练与测量

- 设备：NVIDIA GeForce RTX 4060 Laptop GPU，8GB；PyTorch 2.11.0+cu130。
- 参数：1,048,593；训练事件：192段独立历史×32条=6,144条。
- 训练：第一阶段5,000步，冻结writer后的磁盘读取训练500步，batch size 8。
- 训练脚本总耗时147.02秒；不含此前失败尝试、全部评估和跨进程验证。
- 正常模板测试：8个新owner×96条事件=768条。一次查询仅在当前owner的96条内寻址。
- 600个抽样问题中，480个有已存事件，120个询问未写入的事件；允许重复采样。

| 条件 | 已存事件答对率 |
|---|---:|
| 保证候选含正确事件 | 98.5% |
| 实际动态分组与磁盘读取 | **96.9%（465/480）** |
| 全部地址扫描后读取 | 93.1% |
| 保留地址但清空内容向量 | **0%** |
| 保留地址但错配内容向量 | **15.2%** |
| 未见事件叙述及问题模板 | **0%** |

正常模板、实际分组读取时：Recall@8为100%，120个未知事件问题均输出UNKNOWN；这只是本次样本结果，不表示普遍不会编造。未见模板即使提供正确候选也全部回答UNKNOWN，问题不限于路由。

## 重启后是否还记得

另用不读取数据集的CLI在不同进程中写入并查询两段经历。问题同为“画册项目第1次讨论，当时感受是什么？”：

| 持久化经历中的感受 | 第一次新进程回答 | 第二次新进程回答 |
|---|---|---|
| 尴尬 | 尴尬 | 尴尬 |
| 安心 | 安心 | 安心 |

两个owner严格隔离。同一个问题随保存的经历改变答案；重启后的回答完全一致。结合内容清零/错配消融，支持模型确实使用了持久化内容。

## 失败与限制

1. 最初两次尝试未使用场景属性辅助监督，路由学习失败，实际读取评估全部回答UNKNOWN。最终增加事件/问题地址预测“项目+讨论次数”的训练辅助损失；推理不提供这些标签，也不解析它们后查字典。初始失败日志保留在 `runs/pilot_01` 和 `runs/pilot_02`。不同尝试步数与评估样本量不同，不是严格的因果消融。
2. 输入是有限词表和模板，答案是57类分类。未见叙述和提问方式答对率为0%，当前不能用于自然聊天或真实数字人。
3. 768条测试事件产生628个组，很多近似单事件组。实现有动态加入、拆分、合并，但尚未形成理想的语义事件堆；组内候选少不代表总计算少，因为还要扫描组中心。
4. CPU缓存地址和中心，内容按需从SQLite读取。内存中的索引仍随事件量增长，没有解决任意规模索引；磁盘也有限。没有实现价值遗忘或多级索引。
5. 没有证明内容槽具有干净的语义分工。删去“感受/关注”槽还影响日期，表示可能纠缠。
6. 只有一个最终训练随机种子，测试历史有限；没有验证真实对话、跨事件推理、长期纠错或writer升级后的旧记忆兼容性。

下一轮应先固定架构，扩展和严格隔离表达模板，分别测试“只换问题”和“只换事件叙述”；之后再处理聚类退化和多级磁盘索引。当前不应靠扩大事件库掩盖语言泛化失败。
